# 第一版设计

## 已确认范围

个人使用的 Chrome 插件，手动加载；右键收藏英文单词，内置离线英汉释义；弹窗查看、搜索、编辑、删除和导出；相同 Chrome 账号跨电脑同步。忽略大小写但保留词形。重复收藏不修改原记录。配额满后继续本地保存。自动合并，删除优先。

## 模块边界

右键事件和弹窗请求进入唯一的 Manifest V3 service worker。`Notebook` 的队列将本设备操作串行化，所有改动先持久化到 `storage.local`，再尝试同步。弹窗只发送意图，不直接修改词条存储。`Dictionary` 仅加载插件自身打包的 JSON 分片，支持并发请求合并与有限缓存。

## 词条与合并

规范化单词作为键，值为紧凑数组：`[generation, createdAt, modifiedAt, actor, customDefinition, deleted]`。标准释义不进入同步数据。时间采用毫秒，记录观测到的最大时间，避免同设备连续操作或系统时钟回退产生旧版本。

首次收藏使用空 generation，独立设备对同词的首次收藏可以合并并保留最早时间。一次收藏周期中，删除标记优先；未删除版本按 `(modifiedAt, actor, customDefinition)` 排序。删除后的主动重新收藏生成新 generation，避免永久无法重加，也隔离旧设备上的旧操作。不同 generation 选择较新版本。

合并满足交换律、结合律和幂等性。相同单词的手动编辑若在弹窗打开期间收到了远端更新，会拒绝旧编辑表单覆盖并提示刷新。

## Chrome 同步

将词条哈希分配到 128 个固定 key，每个 key 是词条映射。写入前估计 UTF-8 字节数，检查总配额、单项配额和 key 数量，优先处理删除和现有记录的更新，再尝试新增。总空间或某个分片不足时，保留未能提交的本地状态，不删除其他词。

Chrome 对同一个 key 的并发写入并不提供事务。worker 收到 `storage.onChanged` 时合并 `oldValue`、`newValue` 和本地持久化内容，并在有差异时修复分片。不同设备分别保留自己的已接受操作，以最终合并抵抗分片覆盖。定时重试和每次启动/打开弹窗也执行协调。正常无变化读取不写入，避免事件循环和消耗写入配额。

删除标记不自动清理，因为无法证明长期离线的所有设备都已看到删除。插件不把本地写入成功表述成远端已收到。

## 词典、打包与权限

固定 ECDICT 源版本和 CSV 校验值；过滤出单个英文词与中文释义，按前两个字符打包 754 个 JSON 分片。完整发行目录包含词库，安装时无需下载数据。保留上游许可。

仅使用 `contextMenus`、`storage`、`alarms`。没有网页内容脚本、站点权限、在线 API 或服务器。manifest 固定公钥只用于固定开发版扩展 ID，不是秘密凭证。

## 验证边界

Node 测试覆盖合并代数性质、离线双设备、删除冲突与重加、配额、限流、损坏数据保护、持久化失败和真实词典内容。独立 Chromium 档案检查真实扩展加载、菜单回调、页面交互和下载。真实账号跨电脑同步与系统原生菜单点击另按手工验收执行。
